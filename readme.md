# MakeItMy

Локальный веб-сервис для загрузки музыки из Яндекс Музыки и её воспроизведения через браузер. Работает как персональный сервер на устройстве: принимает ссылку на трек, альбом или плейлист, сохраняет аудиофайлы локально и предоставляет мобильный веб-интерфейс для прослушивания.

Основной сценарий использования — запуск на смартфоне под Termux: устройство одновременно выполняет роль сервера и хранилища.

## Возможности

- Импорт по ссылке: отдельный трек, альбом или плейлист целиком.
- Отслеживание прогресса импорта в реальном времени (Server-Sent Events); треки отображаются в интерфейсе по мере обработки, без ожидания завершения.
- Двухфазная загрузка: сначала компактные версии для быстрого начала воспроизведения, затем полные версии в фоновом режиме.
- Потоковая передача аудио с поддержкой HTTP Range-запросов (206 Partial Content): воспроизведение и перемотка доступны до окончания загрузки.
- Дедупликация: повторный импорт существующих треков не приводит к дублированию записей и файлов.
- Повторное использование ранее загруженных файлов.
- Общие обложки альбомов (один файл на альбом) с автоматическим восстановлением отсутствующих обложек.
- Очистка хранилища: удаление файлов без записей в базе, временных файлов, устаревших обложек; опциональная перекодировка-конвертация тяжёлых (lossless) файлов в компактный формат с повторной постановкой в очередь.
- Виртуализированный список треков: большие плейлисты отображаются без потери производительности.
- Восстановление после перезапуска: незавершённые загрузки и импорты автоматически продолжаются.

## Требования

- Python 3.10 или новее.
- Токен доступа Яндекс Музыки (см. [Конфигурация](#конфигурация)).
- Для запуска под Termux (Android): приложение Termux, доступ в интернет, ~100 МБ свободного места под окружение (плюс место под музыку).

Зависимости Python перечислены в `requirements.txt` и устанавливаются автоматически скриптом `run.sh`:

- Flask — веб-сервер и API;
- yandex-music — взаимодействие с API Яндекс Музыки;
- mutagen — чтение тегов аудиофайлов;
- pycryptodome, strenum — транзитивные зависимости загрузчика.

## Установка и запуск

### Вариант 1. Termux (рекомендуется)

```bash
bash run.sh
```

Скрипт выполняет следующие действия:

1. Устанавливает системные пакеты через `pkg` (только при первом запуске): `python`, `python-pip`, `clang`, `libjpeg-turbo`, `zlib`, `openssl`.
2. Создаёт виртуальное окружение `.venv` (с автоматическим восстановлением `pip`, если он отсутствует).
3. Устанавливает зависимости из `requirements.txt` без использования кеша `pip` (экономия места).
4. Загружает переменные из `.env`, если файл существует.
5. Запускает сервер (`python app.py`).

Адреса для открытия интерфейса:

- на самом устройстве: `http://127.0.0.1:5000`;
- с другого устройства в той же локальной сети: `http://<IP-адрес телефона>:5000`.

### Вариант 2. Настольный компьютер (Linux / macOS)

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

Сервер будет доступен по адресу `http://127.0.0.1:5000` (хост и порт настраиваются, см. ниже).

## Конфигурация

Все параметры задаются переменными окружения. Их можно указать любым из способов:

- непосредственно в окружении;
- в файле `.env` в корне проекта (загружается автоматически, установка `python-dotenv` не требуется);
- частично — через аргументы `run.sh` (скрипт также читает `.env`).

Приоритет значений: переменные окружения имеют precedence над `.env`; `.env` — над значениями по умолчанию.

### Получение токена

Для работы необходим токен доступа Яндекс Музыки (`YANDEX_MUSIC_TOKEN`). Способы его получения описаны в документации библиотеки `yandex-music` (извлечение из официального приложения или веб-версии сервиса).

Токен ищется в следующем порядке:

1. Переменная окружения `YANDEX_MUSIC_TOKEN` (включая значение из `.env`).
2. Файл `very_secret.txt` в корне проекта (поддерживается для обратной совместимости).

Файлы `.env` и `very_secret.txt` исключены из контроля версий (см. `.gitignore`) и не должны попадать в репозиторий.

### Параметры

| Переменная | По умолчанию | Описание |
|---|---|---|
| `YANDEX_MUSIC_TOKEN` | — | Токен доступа Яндекс Музыки. Обязательный параметр. |
| `YM_QUALITY` | `lq` | Качество аудио: `lq` (компактное), `nq` / `hq` (стандартное), `lossless` (без потерь, с откатом к стандартному при недоступности). |
| `YM_COVER_SIZE` | `200` | Разрешение загружаемых обложек в пикселях. |
| `YM_MAX_WORKERS` | `4` | Число параллельных потоков загрузки треков. |
| `YM_TRACK_FETCH_BATCH` | `20` | Размер пакета при запросе метаданных треков у API. |
| `YM_UI_PAGE_SIZE` | `50` | Число треков, возвращаемых API за один запрос. |
| `YM_LOSSLESS_MIN_BYTES` | `6291456` | Порог размера файла в байтах, выше которого аудио считается избыточно тяжёлым и подлежит повторной загрузке в компактном качестве. |
| `YM_DEV_PERF` | `1` | `1` — включать время обработки сервера (`server_ms`) в ответы API; `0` — отключить. |
| `FLASK_HOST` | `0.0.0.0` | Сетевой интерфейс для прослушивания. |
| `FLASK_PORT` | `5000` | Порт веб-сервера. |

Пример файла `.env` (заготовка — в `.env.example`, скопируйте её: `cp .env.example .env`):

```dotenv
YANDEX_MUSIC_TOKEN=...
YM_QUALITY=lq
YM_COVER_SIZE=200
YM_MAX_WORKERS=4
FLASK_PORT=5000
```

## Использование

### Импорт музыки

1. Откройте главную страницу. Вставьте ссылку на трек, альбом или плейлист Яндекс Музыки в поле импорта и отправьте форму.
2. Сервис создаст (или переиспользует) запись плейлиста и начнёт фоновый разбор ссылки.
3. Треки добавляются в базу данных и ставятся в очередь загрузки по мере поступления; страница плейлиста обновляется автоматически через SSE-поток.
4. Добавление дополнительных ссылок в существующий плейлист выполняется со страницы плейлиста (действие «Добавить»).

### Воспроизведение

Страница плейлиста содержит встроенный плеер. Аудио передаётся с локального устройства; при выборе трека с незавершённой полной загрузкой воспроизведение начинается с компактной версии, а полная версия загружается в приоритетном порядке.

### Удаление

- Удаление трека (API) удаляет запись из базы данных и связанные файлы (если они не используются другими записями).
- Удаление плейлиста удаляет его каталог медиафайлов и все связанные записи.

Перед удалением через интерфейс запрашивается подтверждение.

## Архитектура

Приложение построено на Flask и SQLite. База данных SQLite является источником истины: таблицы `playlists` и `tracks` хранят метаданные, статусы загрузки (`queued`, `downloading_short`, `done_short`, `downloading_full`, `done`, `error`) и относительные пути к файлам.

Загрузка выполняется пулом фоновых потоков: короткие (компактные) версии обрабатываются первыми, полные версии ставятся в очередь следом (FIFO). Отдельный однопоточный исполнитель обслуживает приоритетные запросы (нажатие на трек). Повторная отправка уже выполняющейся задачи игнорируется (отслеживание `inflight`).

Логика распределена по модулям пакета `ym_player`:

| Модуль | Назначение |
|---|---|
| `config.py` | Пути, регулярные выражения, переменные окружения, загрузка `.env`. |
| `state.py` | Общее изменяемое состояние: блокировки, исполнители, кеши, клиент API. |
| `db.py` | Подключение SQLite, инициализация схемы и миграции, вспомогательные запросы. |
| `yandex.py` | Клиент Яндекс Музыки, разбор ссылок, вспомогательные функции метаданных. |
| `library.py` | Операции с записями плейлистов и треков, сводная статистика. |
| `media.py` | Индекс локальных файлов, обложки, повторное использование, очистка хранилища. |
| `downloads.py` | Фоновые задачи загрузки, постановка в очередь, восстановление после перезапуска. |
| `imports.py` | Импорт плейлистов по ссылке (синхронное ядро, фоновый обработчик, асинхронный вход). |
| `routes/` | HTTP-слой: страницы (`pages`), API плейлистов и треков (`playlists`), хранилище (`storage`), стриминг (`media`). |

Точка входа `app.py` — тонкая обёртка: она реэкспортирует объект приложения Flask и запускает сервер, поэтому существующие сценарии (`python app.py`, `run.sh`, `import app`) продолжают работать без изменений.

## Справочник API

### Страницы

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/` | Главная страница со списком плейлистов. |
| `GET` | `/playlist/<playlist_id>` | Страница плейлиста с плеером. |

### Импорт и плейлисты

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/import` | Начать импорт по ссылке из поля формы `url`. Перенаправляет на страницу плейлиста. |
| `POST` | `/api/playlists` | Создать пустой плейлист (поле формы `title`). |
| `POST` | `/api/playlists/<playlist_id>/rename` | Переименовать плейлист (поле формы `title`). |
| `POST` | `/api/playlists/<playlist_id>/add` | Добавить ссылку в существующий плейлист (поле формы `url`). |
| `POST` | `/api/playlists/<playlist_id>/delete` | Удалить плейлист вместе с файлами. |
| `GET` | `/api/playlists/<playlist_id>` | JSON-сводка: название, статусы, счётчики треков. |
| `GET` | `/api/playlists/<playlist_id>/events` | SSE-поток прогресса импорта и загрузки. Закрывается при переходе в idle. |
| `GET` | `/api/playlists/<playlist_id>/tracks?offset=&limit=` | Постраничный список треков (максимум 100 за запрос). |

### Треки

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/tracks/<track_id>/prioritize_full` | Приоритетная загрузка полной версии трека. |
| `DELETE` | `/api/tracks/<track_id>` | Удалить трек и его файлы. Возвращает `{"ok": true}`. |

### Хранилище

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/storage` | Статистика использования места (медиа, обложки, база данных, счётчики тяжёлых файлов). |
| `POST` | `/api/storage/cleanup` | Очистка. Параметр `aggressive=1` включает удаление избыточно тяжёлых файлов с повторной постановкой в очередь. При запросе JSON возвращает отчёт; иначе перенаправляет на главную. |

### Медиа

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/media/<track_id>/audio` | Аудиопоток с поддержкой Range-запросов. Предпочитает полную версию, при её отсутствии отдаёт компактную. |
| `GET` | `/media/<track_id>/cover` | Обложка трека. При отсутствии возвращает SVG-заглушку. |

## Обслуживание хранилища

При каждом запуске автоматически выполняется безопасная очистка (без затрагивания тяжёлых файлов, без `VACUUM`): удаляются каталоги плейлистов без записей в базе, файлы без ссылок, временные файлы и пустые каталоги.

Агрессивная очистка (`POST /api/storage/cleanup` с `aggressive=1`) дополнительно:

- удаляет избыточно тяжёлые аудиофайлы и ставит соответствующие треки в очередь на повторную загрузку в компактном качестве;
- удаляет устаревшие файлы обложек рядом с треками (используется общее хранилище `_covers`);
- выполняет `VACUUM` базы данных.

## Устранение неполадок

| Симптом | Вероятная причина и решение |
|---|---|
| `Не найден токен` при запуске | Не задан `YANDEX_MUSIC_TOKEN`: добавьте его в `.env` или окружение, либо создайте `very_secret.txt`. |
| Ошибка `Плейлист не найден` | Ссылка ведёт на приватный/недоступный плейлист либо неверный формат ссылки. Поддерживаются треки, альбомы и плейлисты. |
| Треки зависают в статусе `queued` | Проверьте токен и доступ в интернет; после перезапуска очередь восстанавливается автоматически. |
| Нехватка места на устройстве | Вызовите агрессивную очистку; убедитесь, что `YM_QUALITY` установлен в `lq` или `nq`, а не `lossless`. |
| Порт занят | Измените `FLASK_PORT` в `.env`. |

## Структура проекта

```

run.sh             — запуск под Termux: окружение, зависимости, сервер
requirements.txt   — зависимости Python
.env               — переменные окружения (не коммитится)
ym_player/
  __init__.py      — фабрика Flask-приложения
  config.py        — конфигурация и загрузка .env
  state.py         — общее состояние (блокировки, очереди, кеши)
  db.py            — слой SQLite
  yandex.py        — клиент и разбор ссылок Яндекс Музыки
  library.py       — записи плейлистов и треков
  media.py         — файлы, обложки, очистка
  downloads.py     — фоновая загрузка
  imports.py       — импорт по ссылке
  routes/          — HTTP-маршруты (pages, playlists, storage, media)
download_tracks/   — низкоуровневая загрузка с Яндекс Музыки
static/ templates/ — веб-интерфейс
data/media/        — загруженные файлы (не коммитятся)
library.sqlite3    — база данных библиотеки
```
